# 知识引导的鸟类识别 · 完善版实施方案（v2）

> EECS 442 Fall 2026 · Ziyi Wang, Haoping Wang, Jeffrey Huang, Yinuo Cao
> 基于团队 proposal 与《鸟类识别项目实施方案》（2026-11-22）修订。**v2 把原方案里"待定"的部分全部落实为可执行、可复现的具体规则**，并记录本机实测数据。所有规则都在看测试集结果之前写定。

## 0. 相对原方案的主要修订

| # | 原方案 | v2 修订 | 理由 |
|---|---|---|---|
| 1 | proposal 写 RTX 5090；建议 Linux/WSL2 | 实际硬件 **RTX 5080 16GB**，**原生 Windows** + PyTorch 2.11 cu128 已验证可用，无需 WSL | 本机无 WSL；cu128 官方 Windows 轮子支持 Blackwell |
| 2 | "按相似性或混淆选物种" | **具体规则**：仅用官方训练集，按类别平均属性向量（certainty≥3）的余弦相似度，从 Figure 1 的三种麻雀出发贪心扩到 20 类 | 规则可复现、不看测试集 |
| 3 | "5-6 个部位，明确坐标约定" | 固定 6 个部位：beak, crown, nape, throat, breast, tail；坐标用 **Qwen 原生 0–1000 相对坐标**，与缩放无关，直接映射回原图 | 避免缩放后坐标换算错误 |
| 4 | "预选约 20-30 个属性" | **24 个属性**：从知识条目映射到的 CUB 属性中，按 20 类在 dev 集上阳性率的类间标准差取前 24 | 只保留对这 20 类有区分度的属性 |
| 5 | D 组"长度结构接近的无关文本" | 每条特征替换为一条日常物品句子，按长度最近匹配并在词边界截断；**总字符数与 C 相差 <1%**（单元测试保证 <10%） | 原始做法实测长 27%，已修正 |
| 6 | E 组"交换部分关键特征" | 预先指定 5 对相似种（Chipping↔Clay-colored、Song↔Lincoln、White-crowned↔White-throated、Le Conte↔Nelson、Savannah↔Vesper），**交换每对的前 2 条特征**，其余 10 种保持正确 | 可单独统计"被带偏到搭档物种"的比例 |
| 7 | "部位定位只在有效预测上算误差需报覆盖率" | 主定位指标改为 **PCK@0.1**（漏答记为失败），同时报覆盖率与平均误差 | 让"少答"无法换来更好的分数 |
| 8 | 遮挡控制区"鸟体其他位置" | 控制区 = 与关键部位**最近的、不重叠的可见身体部位**；遮挡为灰色正方形，边长 0.30·√(鸟框面积) | "最远部位"规则实测 83% 落在尾巴上，过于单一 |
| 9 | batch size = 1 | **batch size = 8（左填充）**，五组条件相同批处理 | 实测 bs=1 13 s/图，bs=8 2.1 s/图，峰值显存 12.5 GB |
| 10 | 输出格式未定 | 单行紧凑 JSON，字段顺序为 parts → attributes → species（先观察后判断）；约 290 个输出 token，无截断 | 降低 token 数，便于解析 |

## 1. 研究问题

1. **识别**：正确的鸟种鉴别知识（C）是否比无知识（A）、通用检查清单（B）、等长无关文本（D）提高 mean per-class accuracy？
2. **证据**：知识是否同时改善属性判断（attribute F1）与部位定位（PCK）？分类收益与证据收益在类别层面是否一致？
3. **依赖像素还是文字**：遮挡关键部位是否比遮挡同面积控制区域更多地抹掉知识收益？错配知识（E）是否把模型带偏到搭档物种？

## 2. 数据与知识（已完成）

- 数据：CUB-200-2011。选出的 20 类（`data/splits/species.json`）：18 种麻雀 + American Pipit + Bank Swallow。
- 划分（`data/splits/manifest.csv`）：官方训练集每类 80/20 → **dev 478 / val 120**；官方测试集 **test 585**（仅最终评估用）。
- 知识（`knowledge/species_notes.yaml`）：每种 4 条可见外观特征，来源为 All About Birds 对应物种 ID 页面（用自己的话归纳），每条特征映射到 CUB 部位与属性。不含分布、鸣声、迁徙。
- 知识核对（`results/knowledge_check.md`）：98 条"特征→属性"映射中 75 条被 dev 标注支持。不支持的多来自 CUB 众包标注噪声（例如粉色喙几乎从不被标为 pink），这一点在报告里如实说明，**知识内容不根据测试集修改**。
- 每张图在 C/D/E 条件下都拿到全部 20 个候选物种的知识；候选顺序按图片 ID 固定随机种子打乱，五组完全一致。

## 3. 五组条件

| 条件 | 内容 | 控制目的 |
|---|---|---|
| A | 图像 + 候选物种 | 基线 |
| B | + 通用观察清单（喙、头、喉、胸、背翼、尾） | 控制"多一段观察指令"的影响 |
| C | + 20 种的正确鉴别特征 | 主方法 |
| D | + 与 C 等长、同结构的无关句子 | 控制文本长度 |
| E | + C 中 5 对相似种的前 2 条特征互换 | 检验是否盲从文字 |

单元测试保证：除知识块外，五组的 prompt 逐字相同。

## 4. 推理配置（`configs/default.yaml`）

Qwen3-VL-4B-Instruct，bf16，SDPA attention，贪心解码，max_new_tokens 512，batch 8，图像保持宽高比缩放到像素预算内（边长取 32 的倍数）。像素预算在 **val 集**上于 512² 与 768² 之间选择（A、C 两组平均准确率更高者，平局取更小），之后冻结。

**val 实测结果**：两种预算的输出逐字相同（A 30.0%、C 33.3%）。原因是 CUB 图像最大约 500×500（≤250k 像素），两个预算都不会触发缩放、代码也不放大，所以都是**原生分辨率**；这同时验证了推理完全确定。按规则冻结为 512²（= 原生分辨率）。若想研究分辨率影响，需要主动放大图像，列为稳健性扩展。

## 5. 评估（`src/kgbr/metrics.py`）

| 指标 | 规则 |
|---|---|
| 分类 | mean per-class accuracy；无效/无法解析的回答计为错误；附混淆矩阵 |
| 属性 | 只评 CUB 标注 certainty ≥ 3 的 (图, 属性) 对；"yes" 为阳性，"no"/"unclear"/缺失为阴性；macro & micro F1；单独报 "unclear" 比例 |
| 定位 | 6 个部位中标注可见者：PCK@0.1（误差 ≤ 0.1×鸟框对角线且有预测）、覆盖率、平均归一化误差 |
| 可靠性 | JSON 解析失败率、无效物种率、截断率 |
| 不确定性 | 按类别分层的配对 bootstrap（2000 次），报差值 95% CI 与双侧 p |
| 成本 | 单图耗时、输入/输出 token、峰值显存 |

## 6. 遮挡实验（`src/kgbr/occlusion.py`）

- 子集：测试集中每类取 10 张"关键部位标注可见"的图（种子 442），共 200 张，**只依据标注选，不看预测**。
- 每图三个版本：原图（复用主实验结果）、关键部位遮挡、控制区遮挡；在 A、C 两组运行（800 次推理）。
- 主统计量：**Δ_ctrl − Δ_key**，其中 Δ = Acc(C) − Acc(A)；正值说明知识收益更依赖关键部位像素。结合属性/定位结果解读，不据此声称揭示了内部机制。

## 9. 可选扩展（主线完成后）

1. **监督参考线**：冻结 Qwen3-VL 视觉编码器提取特征 + 线性分类头，用 dev 训练、val 选超参、test 评估；单独标注"使用训练标签"，不与零样本条件同等比较。
2. **QLoRA**：4-bit 基座、只训语言侧 LoRA（rank 8/16）、micro-batch 1 + 梯度累积；构成"有无 adapter × 有无知识"2×2 对照。16GB 显存需先做小批次验证。
3. **稳健性**：换候选顺序种子、换 768² 分辨率复跑 A/C，检查结论是否稳定。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 批处理左填充导致与 bs=1 结果略有差异 | 所有条件使用同样批处理；稳健性检查可用 bs=1 复跑子集 |
| CUB 属性标注噪声大 | 只评 certainty≥3；报告 knowledge_check 结果 |
| 知识提示使输入长度翻倍 | D 组控制长度；报告 token 数与耗时 |
| 结果不显著 | 成功标准是严谨回答问题，阴性结果同样写入报告 |
| Windows 下显存接近 16GB 时推理会卡死（实际发生 2 次，均在长 prompt 的 C/E 组） | 每个 batch 后 `torch.cuda.empty_cache()`；运行可断点续跑，卡住时结束进程重跑即可，结果不受影响（贪心解码确定） |

## 11. 主要结果（测试集，详见 `results/RESULTS.md`）

| 条件 | 准确率 | 属性 macro-F1 | PCK@0.1 |
|---|---|---|---|
| A 无知识 | 35.0% | 47.0 | 59.8 |
| B 通用清单 | 34.4% | 47.8 | 57.0 |
| C 物种知识 | 33.9% | 43.4 | 62.4 |
| D 无关文本 | 33.8% | 43.9 | 58.6 |
| E 错配知识 | 31.8% | 42.7 | 62.2 |

1. **识别（问题 1）：阴性结果。** C 相对 A −1.2 pp（95% CI [−3.4, +1.1]，p=0.32），与等长无关文本 D 完全相同（C−D = 0.0）。正确知识没有提高 4B 模型的零样本识别。
2. **证据（问题 2）：定位改善、属性变差。** C 的 PCK 显著高于 A（+2.6 pp）和 D（+3.9 pp），说明物种知识让模型更准地指出部位；但属性 F1 下降 3.6 pp，且 D 下降幅度相同（C−D 不显著）→ 属性下降是"长 prompt"效应，不是知识效应。类别层面分类收益与证据收益几乎不相关（Spearman ρ≈0.13）。
3. **文字依赖（问题 3）：模型确实在读知识。** 错配知识 E 显著降低准确率（E−A −3.3 pp，p=0.004；C−E +2.1 pp，p=0.006）——错误文字的伤害大于正确文字的帮助。遮挡关键部位比遮挡控制区更伤准确率（A：32.0→25.5% vs 29.0%），但因为 C 本身没有收益，Δ_ctrl−Δ_key ≈ 0（+0.5 pp，CI [−4.0, +5.0]）。
4. **监督参考线：** 同一冻结视觉编码器的特征 + 线性分类器达到 **76.5%**，说明区分这 20 种所需的视觉信息存在于特征中，只是零样本提示（有无知识）都没能用上。
5. **报告建议的叙事：** "知识能改变模型报告的证据（定位）并能误导它，但不足以弥补 4B 模型在细粒度鉴别上的能力短板"；下一步可做 QLoRA（扩展 2），检验"有 adapter 后知识是否开始起作用"。
